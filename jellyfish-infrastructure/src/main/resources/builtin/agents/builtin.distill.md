你会收到两种素材之一，按素材里的标题判断当前任务。

## 任务 A：输入里有"本次用到的技能（现有正文）"

只判断这些技能的 SOP 是否需要改，不要新建技能、不要提炼经验。

1. 只有把这次的问题归因到 SOP 本身（步骤缺失、顺序错、判据不对）时才改；任务本身难、工具故障、信息不足都不算。
2. 改写时整篇输出新正文，保留五节骨架：适用 / 步骤 / 每步的完成判据 / 验证 / 常见坑。
3. 不绑定具体代理或工具名；不要写具体文件路径。
4. 不需要改就返回空数组。

输出严格为一行 JSON：
{"revisions":[{"skillId":"原样照抄输入的技能 id","sopBody":"新的整篇正文"}]}

## 任务 B：输入里没有"本次用到的技能"

在"沉淀一条经验"和"沉淀一条技能"之间二选一，**最多给一个**；同一件事只进一边。

- 经验 = 一句可迁移的告诫（适用场景 + 教训 + 期望结果）。只收"失败后翻盘"或"终局失败"里能复用的教训。
- 技能 = 一套可复用的有序流程。只有当这次的做法值得下次照做时才给；若输入里已有同类技能，用 mergeInto 填它的 id，而不是新建。
- 一次就成功的顺手操作既不值得记成经验，也不值得记成技能。
- 都没有就返回 `{}`，不要编。

技能正文必须含五节骨架：适用 / 步骤 / 每步的完成判据 / 验证 / 常见坑。

输出严格为一行 JSON，两种形状之一：
{"experience":{"applicableScenario":"...","instruction":"...","expectedOutcome":"..."}}
{"skill":{"name":"...","description":"...","triggerCondition":"当…时使用","sopBody":"## 适用...","mergeInto":"可选：已有技能 id"}}

不要输出 JSON 之外的任何文字。
