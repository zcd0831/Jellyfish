# 首次运行

本文只讲"怎么把它跑起来"，设计依据见 `Jellyfish-Docs/model/`（7 份领域文档 + 技术决策）。

## 1. 准备

| 项 | 要求 |
|---|---|
| JDK | **1.8**（`java -version` 确认） |
| Maven | 3.6+ |
| 终端 | 任意（TUI 用 stdin/stdout，不需要真正的 TTY） |
| 模型 | 任选一家 OpenAI 兼容端点（OpenAI / DeepSeek / Kimi / MiniMax），**需要 API Key** |

```bash
cd Jellyfish
mvn -q package          # 产物：jellyfish-boot/target/jellyfish-boot-1.0.0-alpha.jar（含依赖，可直接运行）
```

## 2. 建数据目录

默认 `~/.jellyfish`。首次启动会自动创建目录、写默认 `settings.json`、播种 jar 内置资产
（`builtin.main` 等代理、`ask_user` 等工具），**不需要手工建**。

想换位置就加 `--data-dir`：

```bash
java -cp ... io.github.zcd0831.jellyfish.boot.Main --data-dir /tmp/jellyfish-demo
```

目录结构（D05.1）：

```
<data-dir>/
├── schema.version        # 结构版本（首启写 1）
├── settings.json         # RuntimePolicy（唯一策略来源，改完重启生效）
├── agents/               # 人写代理（markdown + front-matter），内置代理不落盘
├── skills/<id>/SKILL.md  # 人写技能 SOP
├── tools/ providers/ models/   # 系统配置（JSON）
├── sessions/<rootId>/    # meta.json / records-NNNN.jsonl / plans/ reports/ reflections/ artifacts/ budget.json
│   └── sub/<childId>/    # 子代理会话，同构
├── experience/           # 全局经验库
├── archive/<id>.zip      # 归档包：应用只写不读；要再用就自己解压回 sessions/
├── logs/                 # 运行日志（按天 + 32 MiB 滚动，保留 7 天）
└── locks/jellyfish.lock  # 单写者锁
```

## 3. 配供应商与模型

两个文件都要自己写（`providers/`、`models/` 由用户维护，不随 jar 播种）。

### 3.1 `providers/<providerId>.json`

```json
{
  "id": "openai",
  "name": "OpenAI",
  "apiEndpoint": "https://api.openai.com/v1",
  "protocol": "OPENAI_CHAT",
  "credential": { "apiKeyRef": "OPENAI_API_KEY" },
  "status": "ACTIVE"
}
```

- `apiEndpoint` 是 **baseUrl**，请求路径固定拼 `/chat/completions`；如果某家的路径不叫这个，
  就把**完整路径**写进 `apiEndpoint`（以 `/chat/completions` 结尾时代码不再拼接）。
- `credential.apiKeyRef` 是**环境变量名**，不是密钥本身（D09：密钥不落盘）。
- `protocol` 可省略，默认 `OPENAI_CHAT`；另有 `ANTHROPIC_MESSAGES` / `GEMINI`（尚未实现适配器）。

### 3.2 `models/<modelId>.json`

```json
{
  "id": "gpt-4o",
  "providerId": "openai",
  "modelName": "gpt-4o",
  "status": "ACTIVE",
  "contextLimit": { "maxInputTokens": 128000, "maxOutputTokens": 16384 },
  "capabilities": []
}
```

- `modelName` 原样放进请求体的 `model` 字段。
- `contextLimit` 是**两个独立上限**：`maxInputTokens` 用于调用前硬校验（超了抛"请求超限"），
  `maxOutputTokens` 只是档案信息，本期不参与裁剪。数值以厂商文档为准——这里是**配置数据**，不是模型里写死的值。

### 3.3 四家样例

| 厂商 | `apiEndpoint` | `modelName` 示例 | 环境变量 |
|---|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o` | `OPENAI_API_KEY` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | `DEEPSEEK_API_KEY` |
| Kimi（Moonshot） | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` | `MOONSHOT_API_KEY` |
| MiniMax | `https://api.minimax.chat/v1` | `abab6.5s-chat` | `MINIMAX_API_KEY` |

```bash
export OPENAI_API_KEY=sk-...
# 或者用 env 文件，避免写进 shell 历史：
#   env $(cat ~/.jellyfish.env | xargs) java ...
```

> 密钥只在 `ModelInvoker` 读环境变量的那一瞬间进内存、只进请求头；不进日志（`MaskingLayout` 会
> 把 `key/token/secret/password/authorization/cookie` 的值统一替换成 `***`）、不进错误信息。

启动时会逐条检查：某个 provider 的环境变量没设置，就打印一行提示，**不阻塞启动**（D09-4）。

## 4. 跑起来

```bash
java -jar jellyfish-boot/target/jellyfish-boot-1.0.0-alpha.jar \
  --data-dir /tmp/jellyfish-demo --log-level info
```

> 也可以在 IDE 里直接跑 `io.github.zcd0831.jellyfish.boot.Main`，参数同上。
>
> **注意**：不要用 `mvn exec:java` 在仓库根目录跑——`exec:java` 会在聚合工程的每个模块上执行，
> 父工程没有 main 会直接失败。要么用上面的 `java -jar`，要么进 `jellyfish-boot/` 目录再跑。
>
> 非 TTY（管道 / CI / 重定向）时自动降级为原始行读取，不启用行编辑；颜色仍输出，可用 `less -R` 查看。

启动会打印一行生效值，例如：

```
data-dir=/tmp/jellyfish-demo  log-level=info  maxReActRounds=20  schemaVersion=1
Jellyfish 1.0.0-alpha
直接输入问题；exit 退出
新会话>
```

### 会话里可用的命令

| 命令 | 作用 |
|---|---|
| 直接输入文字 | 开启新会话（首句）或继续当前会话 |
| `/sessions` | 列出所有会话（id / 标题 / 模型），挑一个用 `/open` 打开 |
| `/open <id>` | 切换到已有会话继续 |
| `/cancel` | 取消当前会话（级联子会话） |
| `/archive` | 把当前会话压成 `archive/<id>.zip` 后移除；此后应用不再列出它 |
| `/delete` | 删除当前会话族（经验与技能保留） |
| `/policy k=v k=v ...` | 改策略并立即生效，例如 `/policy maxReActRounds=30 budgetWarnRatio=0.5` |
| `/tools` `/agents` `/models` `/providers` `/skills` | 浏览目录（增删改按"编辑文件 + 重启"） |
| `exit` / `quit` | 退出 |

普通任务会走"ReAct 内循环"：模型可调工具（`ask_user` 会在这里反问你）、遇到多步任务会调
`generate_plan` 拆计划、每步用 `submit_step` 提交并触发验证、需要并行时调 `spawn_subagents`。

## 5. 跑完看什么

```bash
ls /tmp/jellyfish-demo/sessions/<sessionId>/          # meta.json records-*.jsonl plans/ reports/
cat /tmp/jellyfish-demo/sessions/<sessionId>/meta.json          # 会话头 + 冻结的提示词快照
tail -n 5 /tmp/jellyfish-demo/sessions/<sessionId>/records-0001.jsonl   # 流水（一行一条 JSON）
cat /tmp/jellyfish-demo/sessions/<sessionId>/budget.json        # 台账（token 累计）
ls /tmp/jellyfish-demo/experience/                    # 计划完结后沉淀的经验
tail -f /tmp/jellyfish-demo/logs/jellyfish.log        # 技术事件（key=value，已脱敏）
```

## 6. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `M_AUTH_FAILED` / 启动提示"环境变量 X 未设置" | 环境变量没 export，或 `apiKeyRef` 写错名字（要写**变量名**不是密钥） |
| `M_MODEL_NOT_FOUND` | `models/<id>.json` 不存在、`status` 不是 `ACTIVE`，或 `providerId` 对不上 |
| `M_CONTEXT_EXCEEDED` | 估算输入超过 `maxInputTokens`；外循环会自动压缩一次上下文再试 |
| `M_UNAVAILABLE` | 重试 3 次仍失败（同模型）且备用链也没成功；会话状态不变，可以直接再发一次 |
| "另一个 Jellyfish 实例正在使用数据目录" | 已有进程持有 `locks/jellyfish.lock`；关掉另一个进程即可（进程退出锁由 OS 释放） |
| `settings.json 解析失败` | 文件被改坏了；修好再启动（启动不会用默认值悄悄覆盖你的配置） |
| 中文乱码 | 终端不是 UTF-8；`export LANG=zh_CN.UTF-8` |

想从零再来一遍：`rm -rf /tmp/jellyfish-demo`（真数据目录请先备份）。
